# 经营看板模块

模块入口为「经营看板 → 销售看板 / 业绩目标」，页面地址分别为 `/#dashboard-sales`、`/#dashboard-targets`。看板通过独立接口读取业务数据，不依赖订单页面、订单分页或业务写入权限。

## 权限

- `dashboard.read`：查看销售看板、筛选、查看统计明细及当前月份公司目标。此权限提供全公司统计数据，不代表仅能查看本人订单。
- `dashboard.targets.manage`：查看年度目标并维护公司月目标；与看板查看权限分别授予。
- 现有管理员在启动时幂等补充这两项权限。其他角色保持原配置，管理员可在「系统管理 → 角色权限」分配。
- 只授予看板权限的账号可独立进入模块，不会请求订单业务数据接口。

## 指标口径

| 指标 | 范围与口径 |
| --- | --- |
| 订单总额 / 每日订单金额 | 所选月份、签单人、客户的已批准销售订单；排除预收款订单、海外提货单、草稿、审批中订单。普通销售按北京时间创建日归属。 |
| 已结清订单数 | 有效订单金额大于零，累计结算额达到有效金额。零金额单保留在总订单数中，但不归为已结清或待回款。 |
| 待回款订单数 / 金额 | 有效订单金额减累计结算额大于零；包含部分付款。 |
| 订单累计已回款金额 | 所选订单截至当前的有效累计结算额，包含预收款核销；不表示所选月份实际现金流入。后续补收和生效变更可能改变历史月份结果。 |
| 本月新增预收款 | 预收款类型的实收流水按登记日期（北京时间）归月；排除核销流水，负数流水冲减。签单人归属由原预收款订单提供。 |
| 当前预收款余额 | 客户资料中的当前余额总和，可按客户筛选，与所选月份无关；按签单人筛选时不展示，以免把客户余额错误分摊给签单人。 |
| 月度目标 / 完成率 | 公司月度目标；仅未筛选签单人及客户时计算完成率。未设置、设置为零分别提示，不进行除零计算；超过100%显示真实比例，进度条最长100%。 |

已生效的聚水潭 `effectiveOrder.total/paid` 覆盖原始订单金额和结算额，按当前配置的聚水潭环境匹配；尚未生效的变更不会提前计入。取消发货不直接等于销售取消或退款，不自动把业绩归零。

结算补录按 `settlement.periodStart/periodEnd` 所属月归属；同月结算在每日图表中集中到期末日并提示。跨月结算暂不计入并提示核对或拆分，不平均分摊。关联同一聚水潭销售单时优先普通订单；冲突的补录整单排除并提示核对，不虚构分摊金额。日期或金额异常的记录会提示排除原因。

普通收款目前未普遍记录实际到账日期，因此本版不宣称提供精确的月度现金到账统计。对公税额需明确税务数据来源和计算规则后另行接入。

## 接口与存储

- `GET /api/dashboard/sales?month=YYYY-MM&owner=&customerId=`：统一返回卡片汇总、每日序列、订单明细、预收款明细、筛选选项、当前月目标和口径提示。
- `GET /api/dashboard/targets?year=YYYY`：返回全年12个月的目标，未设置月份 `amount=null`、`revision=0`。
- `POST /api/dashboard/targets`：请求 `{month, amount, revision}`，金额非负且最多两位小数，最大 `999999999999.99`。金额为零表示明确设置为零。
- 目标保存在独立的 `dashboard_targets` 表，首次保存也使用事务锁和版本校验；并发修改返回409，成功写入同时记录审计日志。
- 月份和筛选项仅作为本机显示偏好保存；业务统计和月目标均以后端为准。
- 目标属于模块配置，不包含在原业务 JSON 备份中；完整 MySQL 备份包含目标。恢复订单业务备份不会覆盖目标，数据库卷需要保留。

## 验证与本地更新

前端单元测试覆盖导航权限、金额与目标显示；后端单元测试和隔离数据库接口测试覆盖统计、核销、已生效变更、期间、目标并发及独立权限。

```sh
npm run build
docker compose -f compose.java-test.yaml --env-file .env up -d --build java-test
npm run check
docker compose up -d --build crm
```

接口测试只允许 `_test` 数据库和 `CRM_TEST_MODE=1`，不得指向真实业务库。部署完成后检查 `http://127.0.0.1:8088/api/status` 与首页引用的 JS/CSS 资源。生产服务器不在默认发布范围内。

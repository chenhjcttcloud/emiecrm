# 聚水潭对接

正式环境统一申请权限时，使用[接口开通与验收清单](JUSHUITAN-PRODUCTION-API-CHECKLIST.md)。

## 已实现

CRM销售订单批准并全额收款后，由有审批及业务写权限的操作员点击“提交发货”。
窗口中选择店铺、填写收件信息、核对每行聚水潭SKU，可查询库存。产品档案的
“聚水潭 SKU 编码”是新提交时的默认对应，已提交订单使用独立快照。

上传前查询普通商品资料，确认SKU启用且有款式编码，并检查店铺类型和库存记录。
库存显示实物、订单占用、仓库待发快照，不承诺库存预留或指定分仓；实际配货以ERP为准。
预收款订单、海外提货单、小数数量、未全额收款的账期订单暂不支持提交。
pay 节点仅记录CRM已收款金额，不调用支付机构，不代表新增收款。

审批状态与发货状态独立。推送成功为“待发货”，不会直接标记已发货。
本地每分钟轮询订单/销售出库，也可手动“同步状态”。异常、取消、部分发货、
出库物流及商品数量单独显示。只统计Confirmed/Archive出库单，按出库单号去重，
按SKU汇总拆单数量；已发货订单也继续核对，支持出库撤销后的状态更正。
每次最多轮询10单，按更新时间轮转；每个订单查询最多20页，未查完不覆盖旧状态。

提交前持久化订单快照和稳定的CRM-订单号；超时保留“待核对”，不会自动重推。
查不到订单满一分钟后，才允许人工重试，沿用原单号。网关也持久化请求摘要与结果，
相同已成功请求直接返回缓存，不再次上传。未知结果冷却5分钟后才接受相同请求重试。
修改过的同号请求被拒绝。提交后客户、商品、金额和审批状态禁止编辑/备份覆盖。
收件信息由独立发货快照保存。订单的“发货详情”提供收件信息、发货备注及取消发货操作。
变更需要 business.write + order.approve 权限及必填原因；CRM原订单和收款流水保留。
发货备注单独保存于发货记录，不等同于CRM订单备注，也不会触发资金退款。

### 订单变更（权限开通和沙箱验收后启用）

网关新增 `/v1/mutations`，仅允许以下三个写接口：

- 修改自有商城收件人 `/open/jushuitan/orderaddress/update`（[官方文档](https://openweb.jushuitan.com/dev-doc?docType=4&docId=1435)）。
- 修改卖家备注 `/open/jushuitan/order/remark/upload`（[官方文档](https://openweb.jushuitan.com/dev-doc?docType=4&docId=196)），CRM输入最多400字，附带原订单号及沙箱标记，总长度不得超过500。
- 按内部单号取消 `/open/jushuitan/orderbyoid/cancel`（[官方文档](https://openweb.jushuitan.com/dev-doc?docType=4&docId=19)）。

网关默认 `JST_ALLOW_ORDER_CHANGE=0`。三个权限均通过、沙箱验收完成后，更新网关并设为1。
CRM读取网关 `/ready` 的环境及 `order_change_enabled`，旧网关、环境不一致或未启用时不开放变更按钮。
本地CRM更新不等于云端网关已经发布；生产发布需单独安排。

写入前重新查询聚水潭订单和出库记录：只处理能唯一对应内部单号的原单，拒绝拆分/合并、
已出库和结果不明确的订单。收件和备注仅允许待付款、异常、待审核或待财审状态，
取消还允许发货中和等待外仓状态，但任何出库记录都需人工核对。
状态检查与仓库操作并非跨系统事务，最终以聚水潭接口的状态限制和回查为准。

先持久化变更ID、操作者、原因、变更前及目标数据，再调用接口。网关按环境+变更ID持久化去重，
同ID不同报文拒绝；未知结果绝不自动重放。CRM仅在查询结果与目标完全一致后显示“已生效”，
然后更新发货快照，保留完整变更记录。接口拒绝保留旧值；超时/未匹配显示待核对并阻止下一次变更，
每分钟及手动同步继续核对。长期不一致需人工检查，不能通过反复点击创建新请求。

### 商品、数量、金额：关联变更单

从原订单“发货详情”点击“变更商品与金额”。客户及原审批保持不变，修改商品、整数数量、
两位小数单价和SKU对应后，生成关联变更单。先校验新商品/店铺，再取消旧聚水潭单；
只有唯一旧单已确认取消且没有出库记录，才能继续新单。

差额为新执行金额减上一次执行金额。增加时先在银行/支付渠道实际补收，减少时先实际退款；
有 payment.write 权限的人员输入准确差额、已启用收退款方式及银行/支付流水号登记。
系统不发起真实扣款或退款，暂不支持用预收款核销差额。无差额的变更无需新增现金流水。

原CRM订单、原商品金额及原收款流水保持历史原值。当前执行商品、金额和新旧聚水潭单号
保存在发货记录的 effectiveOrder / amendment / amendments，并显示在发货详情及订单列表。
订单总额概览按已生效执行金额统计。每次差额写入同一个 receipts 表，type=订单变更，
正数为补收、负数为退款，关联原订单及变更单ID；资金总额为原流水加所有差额，不重复记原收款。
客户预付款余额计算忽略这些银行/支付渠道差额，备份恢复允许经过校验的订单变更负数流水。

旧单取消不明确时保持 WAIT_CANCEL，定时/手动同步继续核对；差额未登记时 AWAITING_FUNDS；
登记后上传稳定的新so_id，新单回查身份、金额、SKU数量一致后才绑定并标记 COMPLETE。
新单失败可继续同一变更单，不能另建重复单；结果不明先回查，五分钟后才允许人工沿用原报文和
原单号重试，差额流水沿用同一ID防重。尚未执行取消的 DRAFT 可放弃；取消后的变更单需继续处理。
所有状态保存于现有发货记录，无需新数据库或新卷。

注意：接口权限和云端网关未更新前，所有新按钮仍关闭。功能完成单元测试不代表真实仓库联调通过。

沙箱待验收：三个接口权限；同一订单两次地址修改（普通上传路径有48小时限制，专用接口需验证）；
备注覆盖回查；取消状态回查；旧单取消后的聚水潭支付记录如何保留、新单收款信息是否造成聚水潭资金报表重复统计（需确认结转口径）；超时核对；正式仓库并发状态限制。本次单元测试不代表真实接口已验收。

## 环境与密钥

本地 .env（忽略版本控制）：

```
CRM_JST_GATEWAY_URL=https://jstapi.emie.cn
CRM_JST_GATEWAY_TOKEN=<网关独立令牌>
CRM_JST_ENV=sandbox
```

网关 /opt/emie-jst/.env 保存聚水潭 APP Key/Secret/access token，CRM只保存网关令牌。
网关独立Docker Compose，96 MiB上限、只监听127.0.0.1:18766，由现有OpenResty提供HTTPS。
网关校验X-CRM-JST-Environment与自己的JST_ENV一致。上传还须JST_ALLOW_ORDER_UPLOAD=1。
生产切换需要两端同时改环境，并替换正式授权、店铺/SKU、白名单；旧订单不跨环境同步。
Token刷新、平台消息回调尚未实现，目前采用主动查询，不要填写本服务为回调接收地址。

## API

均要求CRM登录；读取要求business.read，提交要求business.write + order.approve。

- GET /api/jst/config、/api/jst/shipments：无密钥的状态和发货记录。
- GET /api/jst/shops：店铺分页查询，仅返回可上传的站点。
- POST /api/jst/inventory：`{"skuId":"..."}`。
- POST /api/jst/orders/{CRM订单ID}/submit：shopId、recipient、按原明细排序的items[].skuId。
- POST /api/jst/orders/{CRM订单ID}/sync：人工核对。

业务表jst_shipments与原state JSON分离，普通业务保存不会覆盖发货进度。
CRM备份包含jstShipments；恢复保留已有实时发货记录，新增导入的处理中记录转待核对。
日志只存有限操作描述；不输出密钥。发货记录含收件信息，备份按敏感业务数据保管。

## 网关构建、迁移、卸载

源码在deploy/jst-gateway，服务器部署目录/opt/emie-jst。
必须同时迁移本地CRM数据库与网关data/audit.sqlite3，保留稳定单号与去重记录。
迁移旧服务停止后导出镜像和数据，切换DNS和聚水潭出口IP白名单，验证再恢复提交。
不要同时运行两个相互独立的CRM/网关数据副本。
现有服务器backup.sh、uninstall.sh和README.md包含专用路径清理步骤；不能执行全局prune。

## 账期可行性试验（2026-10-21，已暂停）

业务决定：账期发货暂不开发，保留以下试验结果作历史记录，不列入正式上线待办。

在现有沙箱授权和“CRM测试店铺”下，以相同测试单号分别验证两种传参：

| 场景 | 应付 | 实付 | 上传结果 | ERP实际状态 |
|---|---:|---:|---|---|
| WAIT_BUYER_PAY，不传pay | 0.01 | 0 | code=0、issuccess=true | WaitPay（待付款） |
| WAIT_SELLER_SEND_GOODS，pay.amount=0 | 0.01 | 0 | code=0、issuccess=true | WaitPay（待付款） |

测试订单 EMIE-CREDIT-20261021144010，内部单号5993036，SKU 2609271415-80，数量1。
第二次为更新同一订单，没有新增重复订单。虚拟收件人，备注禁止实际发货。
没有调用审核、出库、支付或发货接口，也没有写入任何正数实收金额。

结论：当前普通订单上传接口/沙箱配置可以接收未付款订单，但本次不能证明它可直接进入
账期发货的待审核流程。上传成功与账期可发货是不同的结果。CRM现有全额收款限制继续保留。
需要聚水潭确认：当前自有商城/ERP版本是否支持未收款赊销订单审核、需要何种店铺或业务配置、
是否有独立B2B/赊销单接口，以及应付、实付、付款状态的正确口径。
未确认前不能用伪造全额支付、把应付改成零、或将货到付款当作账期的方式绕过。

可复用的沙箱脚本：tests/jushuitan-credit-probe.py。仅允许sandbox，在网关容器内执行。
凭证从环境读取，不打印；请求前写入持久标记，网络结果不明确时只回查，不重复写入。
服务器完整报告位于/opt/emie-jst/data/sandbox-credit-probe.json。
正式接入仍需客户账期授权、订单账期审批、到期日和未收应收款台账；这些功能本次未开放。

## 2026-10-21 检查修复

- `editVersion` 仅在订单身份、状态、请求或变更内容变化时更新；普通轮询的时间及日志更新不再使编辑表单过期。
- 旧单取消已确认后，即使关联变更单仍是 DRAFT，也可恢复到待结算或待推送状态；不允许放弃实际已取消旧单的变更。
- 轮询在数据库中先过滤当前聚水潭环境，再选取最旧十条。
- 删除产品同时检查发货快照、执行单及关联变更历史的引用。
- 恢复业务备份时，必须包含并匹配当前聚水潭订单和变更记录，以及全部已登记的差额流水；过旧备份被拒绝。该保护不回滚聚水潭外部状态。
- 切换订单或变更单会清空未提交的收退款登记；非编辑状态的收件信息跟随最新确认快照显示。

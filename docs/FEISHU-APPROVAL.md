# 飞书订单与收款审批

销售订单提交后，CRM 将订单与审批待办一起写入数据库，再由后台调用飞书原生审批接口。保存草稿不会发起审批。审批通过后订单变为“已批准”；驳回、撤回或删除后回到草稿，保留对应飞书审批结果，修改后可重新送审。

在 CRM 明确选择「取消订单」属于另一条流程：未批准、未收款且没有聚水潭或财务关联时才能取消；已有待审批实例须由原发起人撤回并核实飞书返回结果。确认后订单变为“已取消”，锁定内容并保留审批及审计记录。网络结果未知时只允许核对原审批，不能跳过外部确认而取消。

## 配置现有流程

使用国内 CRM 自己的飞书应用凭据与用户身份绑定。在未纳入版本管理的 `.env` 中配置：

```dotenv
CRM_FEISHU_SALES_APPROVAL_CODE=填写现有销售审批的definitionCode
CRM_FEISHU_PREPAYMENT_APPROVAL_CODE=
CRM_FEISHU_RECEIPT_APPROVAL_CODE=
```

销售订单、海外提货单与预收款统一走飞书审批，不再提供 CRM 本地批准或关闭审批后的兼容分支。未配置模板或应用权限时仅可保存草稿，不能以手工修改状态或恢复备份代替飞书审批。原 `CRM_FEISHU_APPROVAL_REQUIRED` 开关已移除，遗留值不改变这一规则。海外提货单使用销售模板中的同名订单类型选项；预收款使用独立模板，不回退到销售模板。

聚水潭结算补录沿用国内独立核对规则，菜单显示「确认结算补录」，不作为普通订单的本地批准入口。已有历史已批准订单继续保留并按原规则维护、收款。

2026-11-23 本地已配置并通过读取校验的国内流程：

| CRM 订单类型 | 飞书流程 | 审批定义 Code |
| --- | --- | --- |
| 销售订单、海外提货单 | 亿觅 CRM · 国内事业部 新建销售订单 | `E596B3A2-7BD2-430B-A8F2-6A106E188050` |
| 预收款订单 | 亿觅 CRM · 国内事业部 预收款单 | `272684D3-8725-4453-9C4E-0B6B69262385` |
| 收款单（含预收款到账和预收款核销） | 亿觅 CRM · 国内事业部 收款单 | `4530CB82-EB2C-4333-8238-280B28C47A05` |

另一个销售模板 `8DAE9904-344D-4ECD-B7BA-5C2BA9BD1AB8` 的接口返回定义与所选销售模板完全相同，采用用户最后提供的销售模板编号。

当前销售模板要求收货人、收货电话、收货地址及逐项商品折扣。收货人和电话可从所选客户的联系人资料初填，地址需填写确认；这些信息可随草稿保存。折扣默认 0，仅按现有海外 CRM 约定写入审批表单，订单金额和小计仍按 CRM 商品数量乘销售价计算，不重复折算。

## 收款审批与入账

2026-11-23 用户确认国内收款改为「飞书审批通过后入账」。配置 `CRM_FEISHU_RECEIPT_APPROVAL_CODE` 后，销售收款页、旧收款入口与订单操作菜单使用同一收款申请；不再通过直接增加订单已收金额记账。未配置此独立模板的环境继续使用原收款模式。

- 订单审批与收款审批是独立流程。销售订单或预收款单审批通过后，仍需登记实际收款并提交收款审批；订单审批本身不记账。
- 申请需填写已批准订单、客户、实际到账日期、模板支持的收款类别、收款方式和分配金额；多订单分配合计必须等于本次金额。聚水潭结算单继续校验实际到账日期，并禁止预收款核销。
- 预收款核销仍表示已有余额抵扣，使用原「预收款核销」方式申请，并在表单中说明没有新增现金到账；审批通过入账时重新检查余额。预收款订单本身不能使用核销方式。
- 提交仅保存审批申请、金额分配和订单及商品快照，不增加订单已收金额、不增加客户余额、不写收款流水、不触发发货。待审批及已通过但尚未入账的申请占用关联订单，防止重复登记或修改审批内容。
- 审批通过后，在事务内更新订单已收金额、流水及客户预收款余额，并记录唯一的入账标志；重复轮询、同步和重试不会重复入账。驳回、撤回或删除均不记账。
- 通过后暂未入账时显示「入账待处理」和原因，保留申请与订单占用；同步或后台重试后再确认入账。未知提交结果继续使用原申请编号和 UUID 核对，不能另建重复申请。
- 审批列表、详情和流程展示真实审批人及动态；新流水保留申请时的商品快照和审批关联。历史流水保留原记录与来源提示。
- 业务 JSON 备份包含收款审批记录，恢复必须与数据库当前审批及已入账流水一致；旧备份不能抹掉待审批申请或回退已入账金额。迁移到空库需单独核验外部审批实例。

收款模板要求「项目」「客户」「收款发生日期」「收款类别」「收款金额（元）」「归属人」，可选附件和备注。类别从实际模板读取，不写死控件 ID。已用国内应用完成该模板的只读预览，当前审批人为曹诵竹；预览不创建实例、不发送审批通知或登记收款。

在[飞书审批管理后台](https://www.feishu.cn/approval/admin/approvalList?devMode=on)找到现有流程，打开编辑页面，地址中的 `definitionCode` 就是审批模板编号。模板必须启用，提交范围覆盖实际发起人，审批节点配置有效的审批人。

飞书应用需要已发布的审批定义读取和实例创建、查询权限。可按[飞书审批 API 文档](https://open.feishu.cn/document/server-docs/approval-v4/approval-overview)授权 `approval:approval`，或使用满足相应接口的细分权限。审批人未在 CRM 绑定时，通过通讯录接口补充姓名，需要 `contact:contact.base:readonly` 和覆盖审批人的通讯录数据范围；缺少姓名权限时流程仍展示实际节点和任务状态，并说明姓名不可用。

配置完成后执行 `docker compose up -d --build crm`。后台同步依靠定时查询，不需要开启长连接。生产发布另行授权。

## 订单与流程

- 点击提交时先检查应用、模板和字段；失败时保留表单供修改，不显示虚假的送审成功。
- 订单和持久化审批任务在同一事务中保存。后台发起失败时可重试；网络超时造成结果未知时保留原 UUID 查询和重试，避免重复创建审批。重复提交须匹配原请求标识与发起人；不同请求生成相同订单编号时返回冲突，不会将另一笔订单当成提交成功。
- 审批中和已通过的订单锁定审批核心内容；备注、附件的维护遵循后端校验。具备 CRM 审批权限也不能直接批准已交给飞书的订单。
- 后台约每 60 秒查询待处理审批，页面支持手动同步。CRM 写回前校验实例、模板、UUID 和发起人，其他审批不会改变订单。
- 订单抽屉的图片附件下方显示审批人、当前与后续节点、处理记录及重新送审历史。飞书不允许预览后续节点时保留已返回的实际流程，并明确提示预览不可用。
- 备份恢复不能覆盖已经关联审批的订单审批核心内容，备份审批记录必须与数据库当前记录一致。含审批的备份不能直接恢复到空数据库；迁移到空库需要另行核对外部审批实例，不能通过普通恢复接口导入未经核对的关联。

## 接口

接口均要求登录和业务读取权限，发起审批另需业务写入权限及已绑定的飞书身份。

| 接口 | 用途 |
| --- | --- |
| `GET /api/feishu/approvals/config` | 模板、应用可用性与当前用户能否送审 |
| `GET /api/feishu/approvals` | CRM 订单的审批摘要 |
| `POST /api/feishu/approvals/orders/{id}/create-and-submit` | 原子保存订单和审批任务，接收 `{data, revision, approval}` |
| `POST /api/feishu/approvals/orders/{id}/submit` | 现有订单送审或明确重试 |
| `POST /api/feishu/approvals/orders/{id}/sync` | 手动核对飞书结果并更新 CRM |
| `GET /api/feishu/approvals/orders/{id}/flow` | 审批节点、审批人、时间线和预览状态 |
| `POST /api/feishu/approvals/orders/{id}/cancel` | 检查订单关联，必要时撤回并核对飞书审批，返回 `{state, approval}` |
| `POST /api/orders/{id}/delete` | 满足条件的销售订单或海外提货单软删除，保留原记录和审计 |

审批表单按字段名称匹配飞书返回的控件 ID，不硬编码控件 ID。支持国内订单的客户、签单人、类型、金额、备注及产品明细等字段；未知必填字段或不兼容的控件会明确报错，不能静默遗漏。

收款审批使用独立接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/feishu/receipt-approvals/config` | 收款模板、类别与当前用户能否提交 |
| `GET /api/feishu/receipt-approvals` | 收款申请、审批与入账状态 |
| `POST /api/feishu/receipt-approvals` | 保存分配与快照并提交审批，需稳定 `requestId` 和当前 `revision` |
| `POST /api/feishu/receipt-approvals/{id}/sync` | 查询审批结果并幂等补入账 |
| `POST /api/feishu/receipt-approvals/{id}/retry` | 沿用原请求与 UUID 核对或重试 |
| `POST /api/feishu/receipt-approvals/{id}/cancel` | 原发起人撤回待审批申请 |
| `GET /api/feishu/receipt-approvals/{id}/flow` | 收款审批人、节点和处理动态 |

查询沿用 `business.read`，提交及撤回沿用现有 `business.write` 与 `payment.write`，并要求绑定飞书身份；不自动增加角色权限。

## 验证

单元测试使用模拟飞书响应，覆盖表单映射、重复送审、未知结果恢复、终态回写、实例匹配及权限保护。隔离 MySQL 测试使用专用测试网络和 `_test` 数据库验证事务与并发；不得向业务数据库注入测试用户或订单。验证不会向真实飞书创建测试审批。

真实联调必须先完成应用权限、模板提交范围和审批人配置，再使用实际订单验证提交与结果同步。

2026-11-23 已使用国内应用身份成功读取上述两个启用中的模板，并用已绑定账号完成创建前的只读流程预览：销售模板返回 2 人审批节点，预收款返回 1 人审批节点，通讯录批量查询成功取得全部参与人姓名。该核验没有创建审批实例或发送通知；提交、通过、驳回与重试写回由隔离数据库和模拟飞书响应回归覆盖。

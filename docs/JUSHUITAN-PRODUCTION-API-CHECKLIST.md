# 聚水潭正式环境接口开通清单

记录日期：2026-10-21。依据当前CRM代码、云端网关白名单和本次沙箱联调整理。
用途：正式应用上线时统一申请权限、核对授权并逐项验收。

业务边界：CRM下单、审批和收款 → 上传聚水潭 → 聚水潭管理库存并下发仓库 → CRM查询出库及物流结果。
仅支持已批准且全额收款的销售订单。账期发货已决定暂不开发，不纳入本清单。

**沙箱成功不代表正式权限已开通。下列所有正式权限截至记录时均待核对；本次没有申请或切换正式权限。**

这些接口由当前运行代码直接调用，缺少任何一项会影响提交或状态同步。

| 商品API | 普通商品资料查询（按sku查询） | `/open/sku/query` | 确认SKU存在、启用，并取得款式编码；有库存记录不等于商品资料有效 | 成功 | 待核对 | [文档](https://openweb.jushuitan.com/dev-doc?docType=2&docId=14) |

## 4. 订单变更新增权限（待申请、待沙箱验收）

| 接口 | 路径 | 当前验证状态 |
|---|---|---|
| 修改自有商城订单收件人信息 | `/open/jushuitan/orderaddress/update` | 已核对官方文档，代码接入；真实调用待验收 |
| 修改订单卖家备注（按内部单号） | `/open/jushuitan/order/remark/upload` | 已核对官方文档，代码接入；真实调用待验收 |
| 订单取消（按内部单号） | `/open/jushuitan/orderbyoid/cancel` | 已核对官方文档，代码接入；真实调用待验收 |

三个权限通过后还需更新云端网关。`JST_ALLOW_ORDER_CHANGE=1` 控制总开关；默认关闭。
本地CRM更新不会发布云端网关。商品、数量、金额的关联变更单及差额流水已接入代码；真实取消重建、收退款登记、失败恢复仍需沙箱验收，尚未生产发布。

### 暂不申请的写接口与消息权限

| 能力 | 当前处理方式 | 本期决定 |
|---|---|---|
| 商品资料上传/更新、店铺商品上传/关系写入 | 当前只读取商品资料，由ERP维护商品 | 不申请写权限 |
| 订单指定发货仓 | 当前不传分仓，由聚水潭分配 | 暂不申请 |
| 订单发货 `/open/order/sent/upload` | 当前CRM不直接确认发货 | 不申请 |
| 出库发货 `/open/orders/wms/sent/upload` | 由聚水潭/仓库完成实际出库 | 不申请，不能用作接收发货结果的接口 |
| 物流同步、库存同步等消息推送权限 | 当前CRM主动轮询，尚无消息验签与接收处理 | 暂不申请、不配置接收地址 |
| 账期/赊销相关扩展 | 已暂停账期方案 | 不纳入上线范围 |

授权回调与物流/库存消息回调是不同用途。不能把任意 `/health` 地址当作授权或业务回调地址。

## 5. 应用授权及上线配置（与业务API权限分开核对）

- [ ] 在正式环境选对自有商城应用及ERP授权公司；不要在开发测试应用中申请正式权限。
- [ ] 记录正式应用名称、APP Key及授权公司名称；APP Secret、access_token、refresh_token只存服务器私密配置，不写本文件、不截图存档。
- [ ] 确认正式授权有效及到期时间。Token自动刷新目前未实现，投产前安排续期方式与负责人；如采用刷新接口，须按当前应用类型单独实现并验证。
- [ ] 当前云服务器实际出口曾验证为 `8.134.130.60`；正式部署时重新从实际调用容器确认出口，并将正式出口IP加入正式应用白名单。迁移后随之更新。
- [ ] 正式调用域名：`https://openapi.jushuitan.com`；测试调用域名：`https://dev-api.jushuitan.com`。域名后的路径按上表。
- [ ] CRM和网关两端环境均设为 `production`；网关换成同一套正式APP Key/Secret/Token，不混用测试授权。
- [ ] CRM仅持有独立的网关令牌；聚水潭密钥仍留在云端。`JST_ALLOW_ORDER_UPLOAD=1` 只在开通和核对完成后启用。
- [ ] 选择正式店铺编号；确认站点支持订单上传。测试店铺 `10402930` 不得直接当作正式店铺使用。

- [ ] `jstapi.emie.cn` 的DNS、HTTPS及续期、反向代理、容器持久化数据正常。
- [ ] 若应用详情仍使用旧的临时授权回调地址，按正式应用当前授权方式处理；本服务尚无授权回调处理，不能直接改成未实现的地址。
- [ ] 按正式应用实际配额记录并发/频次，协调轮询与手工操作。沙箱界面的配额不直接视作正式配额。

## 6. 正式上线逐项验收（尚未执行）

正式上线需单独安排，本清单不是上线执行记录。

1. 店铺查询成功，并确认属于正确的正式ERP公司和店铺。
2. 普通商品资料查询返回启用的正式SKU及款式编码。
3. 库存查询成功，核对仓库和库存口径；空列表与无权限分别处理。
4. 用经授权的正式小额订单验证上传；同时检查顶层code及每单issuccess/o_id。
5. 按上传返回的同一单号查询核对，确认没有重复建单。
6. 由正常仓库流程完成约定的发货，再验证销售出库数量、拆单和运单信息回到CRM。
7. 如启用辅助接口，分别验证店铺商品查询及发货信息查询；结果为空不自动当成失败。
8. 核对失败/超时查单、权限不足与频率限制提示；正式联调完成后更新下方记录。

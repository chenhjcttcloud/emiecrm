# 客户批量导入与聚水潭编号关联

客户管理提供「导入客户」。本功能将取得的客户清单导入 CRM，并建立编号对应关系；不会调用聚水潭客户新增/修改接口，也不会自动将客户档案写回 ERP。

## 使用步骤

1. 在客户管理点击「导入客户」，下载空白 CSV 模板或选择已有 Excel/CSV/TSV 文件。
2. 核对文件列对应的客户名称、聚水潭客户编号、主体、负责人、状态、渠道、联系人及手机等字段。环境与编号类型按文件来源选择，正式/沙箱、线下客户/分销商/买家分别隔离。订单买家使用聚水潭生成的 `buyer_id`，不使用可能跨店铺重复的昵称、`shop_buyer_id` 或订单号。
3. 可批量填补空白主体、负责人、状态和渠道；文件已有值优先。新建客户必须具有客户名称、主体、负责人、状态、渠道、联系人和手机。缺少新建资料但具有名称、外部编号的记录仍可关联已有 CRM 客户。
4. 生成预览，逐行选择新增、关联或跳过。同外部编号已关联的记录默认跳过；同名、同主体记录默认要求人工确认。同主体且不同名称的门店可以明确选择新增。
5. 确认后整批保存。业务数据版本发生变化时必须重新预览；中途校验失败整批不写入。

每批最多 2000 行、50 列、5 MiB。Excel 只接受一张有内容的表；首行为表头，编号及手机号按文本保存。公式、科学计数形式的标识值和超限数据会拒绝，不静默截断。CSV 支持 UTF-8、UTF-8 BOM 和 GB18030，支持带引号的逗号、换行及转义双引号。

关联已有客户只追加外部编号，保留客户资料、负责人、跟进信息和财务余额。新建客户余额为零，余额仍按收款/核销流水计算。导入不接受余额、订单或收款字段。文件内重复外部编号会提示错误，不能以重复文件自动创建第二个客户；不会单凭手机号自动合并。

客户编辑页可以查看和维护聚水潭编号关联。编号按系统、环境、客户类型及文本编号唯一；同一编号不能同时关联两个 CRM 客户。普通业务保存与备份恢复同样校验该约束。客户列表搜索可检索编号，CSV 导出包含 CRM 客户 ID 和全部关联（JSON 文本列）。该导出是 CRM 通用清单，不是已确认的聚水潭客户导入模板。

## 订单客户身份

新构建的聚水潭订单将 `shop_buyer_id` 设为由 CRM 客户 ID 确定的固定账号（`CRM-C-` 加 SHA-256 的前 40 位十六进制），同一客户不同订单、改名后仍保持一致。该账号不直接复用分销商、线下客户或订单买家的外部编号，避免混用不同编号体系。

订单号、支付流水号和金额规则保持独立。已持久化且已尝试提交的原始请求仍沿用原报文，不回写历史聚水潭订单。真实推单仍受既有只读及上传开关控制。本地验证覆盖报文生成；同店铺同买家可能触发 ERP 等待合单，正式启用前需要验证当前店铺合单规则，不能将本地验证视作已完成正式推单验收。

## API 与验证

- `POST /api/customers/import/parse?filename=...`：原始文件体，`application/octet-stream`。
- `POST /api/customers/import/preview`：标准化文本行、默认值、环境与编号类型，返回行级校验、候选客户及业务版本。
- `POST /api/customers/import`：携带同一输入、预览版本与逐行决策，按当前状态重验后提交。

三项接口均要求 `business.read` 和 `business.write`。预览和解析不入库，提交使用事务和行锁，并复用原业务保存、资金校验与客户修改审计。

验证包括文件解析单测、重复/同名/主体候选与关联规则单测、固定买家身份单测、前端列映射和导出测试，以及 `_test` 隔离数据库的权限、版本冲突、并发、重复导入和资金历史保护回归。

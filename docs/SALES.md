# 销售模块

左侧独立「销售」菜单按以下顺序排列：

1. **销售订单信息**：`/#sales-orders`，集中查看销售订单、审批、执行金额、当前回款状态、累计已收和待回款；使用现有订单编辑、审批、发货、修改日志和收款流程。
2. **订单产品明细**：`/#sales-items`，逐行展开销售订单商品，支持月份、客户、签单人、关键字筛选，分页、商品详情及跳转原订单。
3. **订单收款明细**：`/#sales-receipts`，查看收款、预收款、核销和正负差额流水，可登记收款并回查订单。
4. **销售业绩目标**：`/#sales-targets`，按月份、签单人分别维护目标，查看订单业绩、订单累计回款、待完成金额和完成率。

旧 `/#orders`、`/#receipts` 地址自动转到销售模块对应页面。预收款管理、客户管理及产品管理保留单独入口。公司整体目标仍在经营看板中维护，销售人员目标页也提供公司目标设置入口。

销售订单信息默认显示销售订单，可通过列表工具栏的类型选择切换海外提货单或全部订单类型，继续访问既有记录。

## 数据与权限

- 查询销售模块沿用 `business.read`。维护订单沿用 `business.write`，批准订单沿用 `order.approve`，登记收款沿用 `payment.write`。
- 销售人员目标维护沿用 `dashboard.targets.manage`；仅有业务查看权限时可查看完成情况，但不能修改目标。人员目标与公司月目标分别保存，互不覆盖。
- 目标以月份和原始签单人名称为键，不猜测同名人员、改名或离职后的身份关系。历史订单未填写签单人时显示提示，该部分仍计入公司业绩。
- 本模块读取现有 CRM 数据。参考截图仅作为菜单顺序及信息结构的参考，不会自动导入飞书表格的数据。

## 商品明细

- 展开销售订单及其已生效 `effectiveOrder.items`，排除预收款和海外提货单；草稿、审批中及已批准订单都可查看，审批状态单列展示。
- 数量保持最多六位小数，单价和金额保持分精度。商品金额舍入差额从末行起分配，汇总与订单执行金额一致；异常差额会提示核对。
- 历史单位成本仅认可明确的订单行 `unitCost` 或 `costSnapshot.unitCost`，缺失成本和毛利显示「未记录」，不会使用当前商品参考成本推算历史利润。任一匹配行成本缺失时，整体成本和利润汇总不展示。
- 月份按普通订单创建日（北京时间），同月结算补录按所属期间期末日；缺失日期或跨月结算不推算月份。空月份筛选可查看历史明细。
- 汇总覆盖全部匹配记录，导出按钮明确为「导出本页」，导出保留小数精度并对 CSV 公式前缀进行转义。

## 收款明细

- 保留预收款、预收款核销、退款及订单变更差额；金额为有符号流水合计，不等于现金净流入。
- 月份优先按已记录的实际到账日期，缺失时按登记时间转北京时间归月。缺失实际到账日期不会补造。
- 客户归属优先使用流水显式客户 ID，其次原订单客户 ID，再尝试唯一历史名称；孤儿流水保持可读。
- 回款状态取订单当前有效执行金额和累计结算额，不是该笔流水发生当时的历史状态。
- 税率按原始记录展示，税额只使用实际登记字段；不会根据收款方式猜税率。任一匹配记录税额缺失时不展示税额合计。
- 「登记收款」复用既有金额核对及收款方式校验，只有实际收款和分配合计一致才能提交。

## 人员目标

- 已完成业绩与经营看板使用同一后端统计逻辑：已批准销售订单、北京时间归属、结算补录期间、有效执行金额及 ERP 关联去重。
- 订单累计已回款包含核销及截至当前的后续补收，不表示当月现金到账。
- 待完成金额为 `max(月目标 - 已完成订单业绩, 0)`；未设置、显式为零分别展示。超过100%时显示真实完成率，进度条最长100%。
- 人员目标保存在 `sales_targets`，金额为两位小数字符串。保存使用事务及版本校验，首次并发保存也只能成功一次；冲突返回409，前端保留草稿，明确核对最新版本后才能覆盖。修改记录进入操作日志。
- 人员目标属于模块配置，完整 MySQL 备份包含此表；现有业务 JSON 备份和恢复不包含人员目标，也不会覆盖它。

## 接口与验证

```text
GET  /api/sales/items?page=1&pageSize=20&q=&month=&owner=&customerId=
GET  /api/sales/receipts?page=1&pageSize=20&q=&month=&owner=&customerId=&method=
GET  /api/sales/targets?month=YYYY-MM
POST /api/sales/targets  {month, owner, amount, revision}
```

后端单元测试覆盖精度、有效商品记录、期间、分页汇总、人员目标、权限、并发、客户归属和未知税额；`tests/sales.test.mjs` 在 `_test` 数据库中进行完整接口验证，结束后恢复测试快照。`npm run check` 串行运行原业务、看板及销售模块接口回归。

按项目约定验证后自动执行 `docker compose up -d --build crm`，检查本地状态接口及首页静态资源，保留数据库卷；不发布生产服务器。

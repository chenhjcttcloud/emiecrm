# 订单管理与业务明细

「业务管理」下提供统一的「订单管理」入口，包含两个视图，左侧不再单独设置「销售」分组：

1. **订单列表**：`/#sales-orders`，集中查看销售订单、审批、执行金额、当前回款状态、累计已收和待回款，使用现有订单编辑、审批、发货、修改日志和收款流程。
2. **产品明细**：`/#order-items`，逐行展开销售订单商品，支持月份、客户、签单人、关键字筛选、分页、商品详情及跳转原订单，保留数量与金额汇总、历史成本和毛利展示、本页 CSV 导出。旧 `/#sales-items` 自动跳转此视图。

两个视图共用原订单数据和权限，页签及浏览器前进后退均可切换；表单提交或结果待核对时禁用页签，沿用原申请编号和重试路径。明细点击订单编号或「查看所属订单」会切回订单列表并打开原订单详情。订单更新后重新读取明细，不迁移或复制订单数据。

目标管理统一位于「经营看板 → 业绩目标」，包含「公司汇总」（`/#targets-company`）和「人员目标」（`/#targets-personnel`）两个视图。人员目标保留按月、按签单人维护目标、参与部门设置、订单业绩、累计回款、待完成金额和完成率；公司汇总保留年度 12 个月的目标来源及独立公司目标设置。旧 `/#sales-targets` 和 `/#dashboard-targets` 分别跳转对应视图，数据与汇总规则保持。

旧 `/#orders` 自动转到订单管理；旧 `/#receipts` 和 `/#sales-receipts` 统一转到「收款管理 → 收款」（`/#receipt-orders`），销售菜单不再提供重复的收款明细入口。该收款页集中提供新建收款、审批列表及已入账流水，支持收款月、签单人、客户、收款方式和关键字联合筛选，展示回款状态、税率税额及产品明细，支持回查原订单、本页导出与全部匹配导出。汇总与导出使用相同筛选，全部匹配导出在单个只读事务中完成。审批中的申请不计入已入账流水，核销及负数调整继续按原记录展示。

「收款管理」下另有「预收款」入口；客户管理及产品管理保留单独入口。公司整体目标自动汇总销售人员月目标，人员目标视图展示当月合计，并可在同一入口切换公司汇总。

订单管理默认显示销售订单，可通过列表工具栏的类型选择切换海外提货单或全部订单类型，继续访问既有记录。

## 与海外 CRM 一致的操作体验

- 点击订单编号或「详情」打开只读订单详情，集中查看客户、金额、商品、收件资料、附件、审批人和处理记录。查看详情无需取得订单编辑权限。
- 订单操作收拢到「操作」菜单，按当前权限、订单状态及外部关联显示编辑、收款、发货、审批同步、取消和删除等入口。
- 普通销售订单、海外提货单、预收款和聚水潭结算补录的审批结果均由飞书回写，不提供本地「批准」或「确认结算补录」。普通订单缺少模板时仅可保存草稿；结算补录缺少销售审批模板时不能提交。
- 聚水潭结算补录复用销售审批模板，以一条明确的结算汇总及关联 ERP 销售单摘要展示审批内容；已发货结算无需填写收货资料或选择计划发货仓库，审批不再次发货。已有待审批补录可从操作菜单发起飞书审批，驳回后可重新送审，历史已批准补录继续保留。
- 订单表单使用统一的可搜索选择器，支持键盘选择；客户继续按稳定 ID 区分，同名客户保留主体等辨识信息。
- 普通销售订单和海外提货单的草稿可选填聚水潭发货仓库，送审时核验真实有效仓库并将计划仓库写入审批备注。计划仓库随草稿保留并在订单详情展示，送审后锁定；后续手动发货默认带入，国内原收款与发货条件保持。
- 预收款可以选填参考商品，预收款金额独立填写，参考商品合计不会代替预收款金额；收款发生日期和类别仍需按国内模板明确选择。
- 未批准、未收款且没有聚水潭或财务关联的订单可以取消；已有待处理飞书审批时，需由原发起人撤回并核对外部结果后才取消。安全条件满足的销售订单及海外提货单可软删除，保留底层记录和审计，列表不再显示。
- 已取消或软删除订单不再作为有效业绩、可收款订单或待回款统计对象；已发生的真实财务流水继续保留和统计。

国内现有收款权限、金额核对、预收款核销、结算单到账日期及发货条件保持。2026-11-23 按用户确认新增独立飞书收款审批，配置收款模板后改为审批通过才入账；收款审批不触发发货。配置与状态约定见[飞书审批](FEISHU-APPROVAL.md)。

## 数据与权限

- 查询销售模块沿用 `business.read`。维护订单沿用 `business.write`，批准订单沿用 `order.approve`，登记收款沿用 `payment.write`。
- 销售人员目标维护沿用 `dashboard.targets.manage`；仅有业务查看权限时可查看完成情况，但不能修改目标。人员目标按参与范围汇总为公司月目标，原手工公司目标仅在全部部门参与且整月尚无人员目标时作为备用值。
- 目标以月份和原始签单人名称为键，不猜测同名人员、改名或离职后的身份关系。历史订单未填写签单人时显示提示，该部分仍计入公司业绩。
- 本模块读取现有 CRM 数据。参考截图仅作为菜单顺序及信息结构的参考，不会自动导入飞书表格的数据。

## 商品明细

- 展开销售订单及其已生效 `effectiveOrder.items`，排除预收款和海外提货单；草稿、审批中及已批准订单都可查看，审批状态单列展示。
- 数量保持最多六位小数，单价和金额保持分精度。商品金额舍入差额从末行起分配，汇总与订单执行金额一致；异常差额会提示核对。
- 历史单位成本仅认可明确的订单行 `unitCost` 或 `costSnapshot.unitCost`，缺失成本和毛利显示「未记录」，不会使用当前商品参考成本推算历史利润。任一匹配行成本缺失时，整体成本和利润汇总不展示。
- 月份按普通订单创建日（北京时间），同月结算补录按所属期间期末日；缺失日期或跨月结算不推算月份。空月份筛选可查看历史明细。
- 汇总覆盖全部匹配记录，导出按钮明确为「导出本页」，导出保留小数精度并对 CSV 公式前缀进行转义。

## 收款明细

- 保留预收款、预收款核销、退款及订单变更差额；金额为有符号流水合计，不等于现金净流入。
- 月份优先按已记录的实际到账日期，缺失时按登记时间转北京时间归月。缺失实际到账日期不会补造。
- 客户归属优先使用流水显式客户 ID，其次原订单客户 ID，再尝试唯一历史名称；孤儿流水保持可读。
- 回款状态取订单当前有效执行金额和累计结算额，不是该笔流水发生当时的历史状态。
- 税率按原始记录展示，税额只使用实际登记字段；不会根据收款方式猜税率。任一匹配记录税额缺失时不展示税额合计。
- 「登记收款」复用既有金额核对及收款方式校验，只有实际收款和分配合计一致才能提交。
- 启用独立收款模板后，提交先保存收款申请，通过后才计入已收金额和收款流水；待审批及入账待处理金额不混入既有流水汇总或 CSV。驳回或撤回不记账。订单菜单和收款页使用同一入口，并显示独立的收款审批列表与流程。
- 预收款到账及已有余额核销也沿用审批后入账，核销继续扣减已有余额，不代表新增现金到账。重复同步不会重复记账；通过但入账失败时保留申请供核对重试。
- 收款时可以展开关联订单的商品，登记后的流水详情和 CSV 可查看商品资料。新流水展示登记时的商品快照；旧流水没有快照时，按当前关联订单展示并注明来源，无法关联的记录保持未知，不伪造历史商品。

## 人员目标

- 已完成业绩与经营看板使用同一后端统计逻辑：已批准销售订单、北京时间归属、结算补录期间、有效执行金额及 ERP 关联去重。
- 订单累计已回款包含核销及截至当前的后续补收，不表示当月现金到账。
- 待完成金额为 `max(月目标 - 已完成订单业绩, 0)`；未设置、显式为零分别展示。超过100%时显示真实完成率，进度条最长100%。
- 人员目标保存在 `sales_targets`，金额为两位小数字符串。保存使用事务及版本校验，首次并发保存也只能成功一次；冲突返回409，前端保留草稿，明确核对最新版本后才能覆盖。修改记录进入操作日志。
- 公司目标按参与范围内同月份已设置人员目标精确合计，页面上的姓名搜索和临时部门筛选不会改变公司合计。未设置不计入；设置为 0 也算已设置，全部为 0 时合计为 0。调整后重新进入或刷新看板即可读取新合计。
- 所属部门读取用户资料中的当前部门，部门调整后历史月份也显示当前归属。未分配部门、未匹配到账号的历史签单人、多人使用相同姓名分别标注，不猜测归属。停用部门仍保留展示。
- 支持按部门筛选，并与人员搜索组合；部门使用 ID 区分，同名部门不会混在一起。公司当月目标总额覆盖参与范围内全部人员，另展示当前筛选的目标小计，两者互不替代。
- 人员目标属于模块配置，完整 MySQL 备份包含此表；现有业务 JSON 备份和恢复不包含人员目标，也不会覆盖它。

## 参与部门设置

- 系统管理员可在「业绩目标 → 人员目标」的「参与部门设置」中配置所有账号、所有月份共用的参与范围，权限为 `system.manage`，不等同于维护个人目标金额的权限。
- 默认「全部部门参与」保持原有人员和目标口径，包含以后新建的部门，也保留未分配、未匹配及重名人员。
- 「仅勾选部门参与」只显示当前唯一匹配到选中部门的人员，并且只有这些人的个人目标纳入公司目标。没有部门或归属不明确的人员不纳入指定范围；勾选父部门不会自动包含未勾选的下级部门。
- 指定范围内没有可用目标时，公司目标为 0；选空表示无人参与。指定模式不回退至原手工公司目标，原手工金额及隐藏人员的目标记录仍保留。重新启用部门后，已有目标重新参与汇总。
- 部门变动或人员同名冲突会按当前资料重新判断参与范围。已经删除的部门 ID 不会自动替换为同名部门；配置页提示失效项，管理员可重新保存有效选择。
- 范围设置只调整目标人员列表和目标金额合计，不改变订单、商品明细、收款流水和实际业绩统计口径，也不充当订单数据访问权限。
- 设置通过版本校验保存，冲突返回409并保留界面草稿，需要核对最新配置后再保存；修改记录进入操作日志。完整 MySQL 备份包含 `sales_target_scope`，原业务 JSON 备份不包含此配置。

## 接口与验证

```text
GET  /api/sales/items?page=1&pageSize=20&q=&month=&owner=&customerId=
GET  /api/sales/receipts?page=1&pageSize=20&q=&month=&owner=&customerId=&method=
GET  /api/sales/targets?month=YYYY-MM
POST /api/sales/targets  {month, owner, amount, revision}
GET  /api/sales/target-scope
POST /api/sales/target-scope  {mode, departmentIds, revision}
```

人员目标 GET 行增加 `departmentId`、`department`、`departmentStatus`，状态为 `assigned` / `unassigned` / `unmatched` / `ambiguous`；可选部门列表由 `options.departments` 返回。此接口沿用业务查看权限，仅查询需要的部门信息，不依赖系统用户管理权限，也不返回其他人员资料字段。

人员目标报告通过 `scope` 返回当前参与模式和版本，`rows`、`options.owners`、`options.departments` 均按参与范围返回。范围外人员的目标保存被拒绝，但底层目标不删除。独立 `target-scope` GET/POST 需要系统管理权限，返回当前配置、全部部门及失效部门 ID；`mode=all` 要求 `departmentIds=[]`，`mode=selected` 允许空数组。

后端单元测试覆盖精度、有效商品记录、期间、分页汇总、人员目标、权限、并发、客户归属和未知税额；`tests/sales.test.mjs` 在 `_test` 数据库中进行完整接口验证，结束后恢复测试快照。`npm run check` 串行运行原业务、看板及销售模块接口回归。

`tests/overseas-alignment-api.test.mjs` 补充真实 HTTP 与隔离 MySQL 验证：取消及软删除不可复活、客户改名保留归档、归档订单不能变更聚水潭关联、预收款商品合计独立、新收款商品快照不可随商品资料变动、历史商品回退不写入备份，以及原有收款金额和权限规则。

按项目约定验证后自动执行 `docker compose up -d --build crm`，检查本地状态接口及首页静态资源，保留数据库卷；不发布生产服务器。
